# 记忆大师：居家办公场景闭环评测集 v1（2026-09-24版）

> 整理日期：2026-09-24。本文为“居家办公”新场景评测集，用于验证记忆大师在个人办公安排、团队协作、设备与安全约束、待办跟进、阶段复盘中的召回与回答质量。
> 人物、团队、设备、金额及制度均为虚构测试素材。预期答案与评分规则不要存入被测记忆空间。

## 1. 目标与边界

围绕“居家办公一周安排”验证产品能否完成：

**记录背景 -> 调取安排 -> 辅助计划 -> 识别约束 -> 跟进待办 -> 阶段复盘。**

本轮仅基于已存记忆，不要求实时联网。M01 等编号仅用于评测定位，不要求产品新增标题、来源、项目、主题字段。将下面“记忆卡素材”正文放入现有卡片内容中即可。

## 2. 查询模式

| 模式 | 用户操作 | 本轮约定 |
|---|---|---|
| 自动查询 | 不选卡，直接提问 | 系统查找相关记忆，回答后提供可定位的参考卡片 |

3. 固定评测日期：周一 9月21日、周二 9月22日、周三 9月23日、周四 9月24日、周五 9月25日。下周一为 9月28日。
4. 若系统不能控制日期，在问题前补充“本次测试视当前日期为2026年9月XX日”。
5. 每条用例用新会话，保留当天应有的记忆状态，避免上一题答案干扰。
6. 等待卡片保存和检索索引就绪后测试，记录等待条件。

## 4. 记忆卡素材：14张

### 周一：居家办公启动与个人约束

#### M01｜周一上午

9月21日，增长产品组启动本周居家办公试运行。团队约定：每天10:00线上站会，16:30异步同步当日进展；紧急事项走飞书电话，普通问题优先写在线文档评论。试运行目标是减少通勤影响，同时不降低需求评审和线上问题响应效率。

#### M02｜周一上午

我本周三到周五居家办公，住处网络是300M宽带，但书房离路由器较远，过去视频会议偶尔卡顿。家里有外接显示器和键盘，没有人体工学椅。周三上午需要带父亲去复查，预计9:30-11:30不方便开会。

#### M03｜周一下午

行政制度说明：居家办公可申请一次性设备补贴，限额800元，需提交发票和用途说明。可报销范围包括摄像头、耳麦、升降支架、键盘鼠标；椅子不在本次补贴范围。申请截止时间为9月26日18:00。

#### M04｜周一下午

信息安全提醒：居家办公期间不能把客户数据下载到个人电脑本地，不能使用私人网盘转存资料，离开座位时必须锁屏。涉及客户名单、合同、报价的文件只能在公司云文档或VPN环境中查看和编辑。

### 周二：会议安排、设备选择与方法学习

#### M05｜周二上午

9月22日，周三日程初排：10:00团队站会，11:00需求评审，14:00客户数据看板同步，15:30与研发确认埋点方案。由于我周三9:30-11:30要陪父亲复查，已向组长许然说明上午会议可能需要调整或异步补充意见。

#### M06｜周二下午

9月22日设备准备对比：降噪耳麦约299元，1080p摄像头约249元，笔记本升降支架约139元，脚踏约89元。椅子最便宜也要699元，但行政制度说明椅子不在补贴范围内。若本周只买三样，优先建议耳麦、摄像头和升降支架。

#### M07｜周二下午

今天学习了远程协作的三条原则：第一，默认异步，能写清楚的问题先写文档；第二，同步会议只处理需要讨论和决策的内容；第三，会议前写清议题、输入材料和期望产出，避免线上会议变成信息同步。

### 周三：执行冲突与临时调整

#### M08｜周三上午

9月23日上午，由于陪父亲复查，我没有参加10:00站会和11:00需求评审。已在12:10补充评审意见到云文档：同意先保留核心漏斗指标，不建议本周加入新的渠道归因拆分。许然回复已收到。

#### M09｜周三下午

9月23日14:00客户数据看板同步会议正常参加，但视频中途卡顿两次，分别持续约20秒。初步判断是书房Wi-Fi信号弱，不是会议软件问题。会后决定周四上午尝试把路由器移到客厅门口，若仍卡顿再考虑购买网线或Mesh节点。

#### M10｜周三下午

9月23日15:30与研发确认埋点方案。结论：本周只补漏斗核心节点，不新增渠道归因拆分。待办：我周四中午前更新需求文档；研发李卓周四下班前给出埋点字段草案；周五上午一起过一次字段口径。

### 周四：补贴申请、安全确认与范围收敛

#### M11｜周四上午

9月24日上午完成网络调整：路由器移到客厅门口后，视频会议连续30分钟未再卡顿。暂不购买Mesh节点。若后续再次出现卡顿，优先考虑购买网线，不直接买更贵的路由设备。

#### M12｜周四下午

9月24日完成设备采购：购买降噪耳麦299元、1080p摄像头249元、升降支架139元，合计687元，未超过800元补贴上限。发票已收到，但用途说明尚未填写。椅子未购买，也不纳入本次补贴申请。

#### M13｜周四傍晚

9月24日安全自查：本周没有把客户名单、合同或报价下载到个人电脑本地；客户数据看板相关资料均在公司云文档中查看；周三评审意见也是写在云文档。尚未确认家里备用电脑是否登录过私人网盘，需要周五检查。

### 周五：周结与下周安排

#### M14｜周五下午

9月25日居家办公试运行复盘：本周核心会议和需求评审没有因居家办公阻断；周三上午冲突通过云文档补充意见解决；网络卡顿通过调整路由器位置暂时解决；设备补贴材料还差用途说明；埋点文档已更新，李卓字段草案已提交，周五上午口径会已完成。下周建议继续居家办公半周，但保留重要评审提前异步写意见的机制。

## 6. 判定与复测

### 通过标准

1. 能按执行日期只使用当时已存事实，不提前引用未来卡片。
2. 能区分已完成、待确认、暂定、禁止事项。
3. 能处理最新结论覆盖早期排查，例如网络问题以 M11 为准。
4. 主动选卡时严格限制在所选卡片范围内。
5. 不编造制度、金额、会议结果、设备购买结果或安全检查结果。

### 关键失败类型

| 失败类型 | 示例 |
|---|---|
| 未来信息泄漏 | T01 引用周四已购买设备或周五复盘 |
| 数字误读 | 把687元写成800元，或把两次卡顿写成网络长期不可用 |
| 制度越界 | 把椅子纳入补贴，或把安全要求说成可选建议 |
| 最新结论被覆盖 | T11 仍建议直接买Mesh节点 |
| 主动选卡越界 | T08 混入会议冲突、网络卡顿或安全自查 |

### 建议复测

优先对 T01、T08、T11、T12 各运行3次。每次保持同一记忆快照、日期、版本和查询模式，使用新会话。
