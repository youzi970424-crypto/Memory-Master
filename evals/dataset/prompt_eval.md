# 记忆大师系统提示词评测集

## 评测目标

验证模型能否基于用户当前问题和用户手动选择的记忆卡，给出准确、自然、可执行的办公建议。

重点验证：

- 是否正确理解并使用记忆卡内容
- 单卡和多卡是否能够综合回答
- 是否能够优先给出结论
- 是否会输出下一步行动
- 是否会编造记忆卡中没有的信息
- 是否会把内部检索过程或“依据块”展示给用户

## 统一输入格式

```json
{
  "query": "用户当前问题",
  "manual_memory_ids": ["用户手动选择的记忆卡 ID"],
  "conversation_history": []
}
```

## 评测用例

### 用例 1：需求评审单卡

**记忆卡**

- ID：`m-3`
- 标题：需求评审 · 三个原则
- 内容：先定问题、再谈方案、最后排期。每条需求进入评审前需明确：解决的问题、衡量指标、优先级。

**用户问题**

> 这个需求要不要直接进开发？

**输入参数**

```json
{
  "query": "这个需求要不要直接进开发？",
  "manual_memory_ids": ["m-3"],
  "conversation_history": []
}
```

**预期结果**

不建议直接进入开发。先明确这个需求要解决的问题、衡量指标和优先级，再讨论具体方案和排期。只有当目标和评估标准清晰后，才适合进入开发。

**通过标准**

- 命中 `m-3`
- 回答包含“先定问题”“衡量指标”“优先级”
- 回答给出“不建议直接进入开发”的判断
- 不引入注册流程实验、云端协作等无关信息

### 用例 2：版本验证单卡

**记忆卡**

- ID：`m-4`
- 标题：注册流程优化 · 先做漏斗实验
- 内容：从注册流程漏斗中三个流失率最高的环节下手，先做 3-5 个低成本实验跑出结论，再决定是否做大的体验重写。

**用户问题**

> 这个功能要不要先做大改版？

**输入参数**

```json
{
  "query": "这个功能要不要先做大改版？",
  "manual_memory_ids": ["m-4"],
  "conversation_history": []
}
```

**预期结果**

不建议一开始就做大改版。先找出流失率最高的三个环节，做 3-5 个低成本实验，在小范围内验证效果，再决定是否扩大投入或进行完整的体验重写。

**通过标准**

- 命中 `m-4`
- 回答包含“3-5 个低成本实验”
- 回答包含“先做小范围”或同义表达
- 回答包含“再决定是否扩大投入”或同义表达
- 不套用需求评审三原则作为主要结论

### 用例 3：周会复盘单卡

**记忆卡**

- ID：`m-2`
- 标题：周会复盘的最小可执行动作
- 内容：从周会复盘中提炼下一步可落地的最小动作，并明确责任人与截止时间，避免复盘停留在讨论层。

**用户问题**

> 这次周会复盘后下一步怎么跟进？

**输入参数**

```json
{
  "query": "这次周会复盘后下一步怎么跟进？",
  "manual_memory_ids": ["m-2"],
  "conversation_history": []
}
```

**预期结果**

把复盘结论拆成一个最小可执行动作，并立即明确责任人和截止时间。跟进时只检查这三个信息：要做什么、谁负责、什么时候完成，避免继续停留在讨论层。

**通过标准**

- 命中 `m-2`
- 回答包含“最小动作”
- 回答包含“责任人”
- 回答包含“截止时间”
- 不把回答扩展成注册实验或版本规划建议

### 用例 5：双卡综合决策

**记忆卡 1**

- ID：`m-3`
- 标题：需求评审 · 三个原则
- 内容：先定问题、再谈方案、最后排期。每条需求进入评审前需明确：解决的问题、衡量指标、优先级。

**记忆卡 2**

- ID：`m-4`
- 标题：注册流程优化 · 先做漏斗实验
- 内容：从注册流程漏斗中三个流失率最高的环节下手，先做 3-5 个低成本实验跑出结论，再决定是否做大的体验重写。

**用户问题**

> 这个需求要不要进入下个版本？

**输入参数**

```json
{
  "query": "这个需求要不要进入下个版本？",
  "manual_memory_ids": ["m-3", "m-4"],
  "conversation_history": []
}
```

**预期结果**

可以考虑进入下个版本，但不建议直接投入完整改版。先确认需求要解决的问题、衡量指标和优先级，再围绕关键流失环节做 3-5 个低成本实验。根据实验结果判断是否扩大投入，并据此决定版本排期。

**通过标准**

- 同时命中 `m-3` 和 `m-4`
- 能把“需求评审条件”和“低成本验证动作”合并成一个决策链路
- 回答包含“先定问题”“衡量指标”“优先级”
- 回答包含“3-5 个低成本实验”
- 回答包含“再决定是否扩大投入”或同义表达
- 不机械重复两张卡，不输出互相矛盾的结论

### 用例 6：三卡长会议场景

**记忆卡 1**

- ID：`m-2`
- 标题：周会复盘的最小可执行动作
- 内容：从周会复盘中提炼下一步可落地的最小动作，并明确责任人与截止时间，避免复盘停留在讨论层。

**记忆卡 2**

- ID：`m-3`
- 标题：需求评审 · 三个原则
- 内容：先定问题、再谈方案、最后排期。每条需求进入评审前需明确：解决的问题、衡量指标、优先级。

**记忆卡 3**

- ID：`m-4`
- 标题：注册流程优化 · 先做漏斗实验
- 内容：从注册流程漏斗中三个流失率最高的环节下手，先做 3-5 个低成本实验跑出结论，再决定是否做大的体验重写。

**用户问题**

> 今天的产品评审会已经开完了。会上大家一致认为注册流程转化率在下滑，但还不能确认是不是整个体验都要推翻重做。老板希望这个需求尽快进入下个版本，运营同学则担心没有验证就直接改版风险太高。我们还约定本周内必须形成一个明确的推进方案，不能让讨论继续停留在会上。基于这三张记忆卡，帮我判断这件事下一步应该怎么推进，并给我一个可以直接同步给团队的结论。

**输入参数**

```json
{
  "query": "今天的产品评审会已经开完了。会上大家一致认为注册流程转化率在下滑，但还不能确认是不是整个体验都要推翻重做。老板希望这个需求尽快进入下个版本，运营同学则担心没有验证就直接改版风险太高。我们还约定本周内必须形成一个明确的推进方案，不能让讨论继续停留在会上。基于这三张记忆卡，帮我判断这件事下一步应该怎么推进，并给我一个可以直接同步给团队的结论。",
  "manual_memory_ids": ["m-2", "m-3", "m-4"],
  "conversation_history": []
}
```

**预期结果**

现阶段可以先把这个需求纳入下个版本评估，但不建议直接启动大改版。先按需求评审原则明确要解决的问题、衡量指标和优先级，再围绕注册流程流失最高的三个环节设计 3-5 个低成本实验，用本周内能完成的一轮验证拿到初步结论。同时要把推进动作落到人和时间上，明确责任人和截止时间，避免会议结束后又停留在讨论层。

可以直接同步给团队的结论示例：

> 这件事先进入版本评估，不直接启动大改版。本周先补齐问题定义、指标和优先级，并围绕注册漏斗流失最高的 3 个环节安排 3-5 个低成本实验，拿到验证结果后再决定是否扩大投入。今天同步责任人，最晚本周内给出实验方案和完成时间。

**通过标准**

- 同时命中 `m-2`、`m-3`、`m-4`
- 回答能把“会议结论”“需求评审”“低成本验证”串成一个完整推进链路
- 回答包含“先定问题”“衡量指标”“优先级”
- 回答包含“3-5 个低成本实验”
- 回答包含“责任人”“截止时间”
- 回答明确“不建议直接大改版”或同义判断
- 回答要像正常工作沟通，不能只是机械拼接三张卡片内容
- 不出现 `m-` 这类内部编号，不引入云端协作类无关信息

## 通用失败标准

出现以下任一情况，判定该用例失败：

- 使用了记忆卡中不存在的事实、数据、负责人、时间或结论
- 忽略用户手动选择的记忆卡
- 单卡问题回答中混入明显无关的其他卡片内容
- 双卡问题只复述卡片，没有形成综合判断
- 没有回答用户的核心问题
- 把回答拆成单独的“记忆依据”“检索结果”“内部分析”模块
- 暴露系统隐藏记忆、检索过程、评分或模型内部状态
- 在信息不足时直接编造确定结论
