# 记忆网设计方案

> 版本：v0.1  
> 适用范围：记忆大师 1.1 及后续版本  
> 产品边界：PC 客户端、用户可见记忆卡、隐藏后台记忆、混合 RAG

## 1. 设计背景

记忆卡解决的是“把工作信息保存下来”，但当卡片数量增加后，用户仍然会遇到三个问题：

1. 只搜到单张卡，无法快速理解它和其他判断、反馈、方案之间的联系。
2. 同一个问题涉及多个时间点和多个角色，用户需要手动拼接背景。
3. 新结论、旧结论和替代方案之间的变化不容易被发现。

记忆网的作用，是把记忆卡之间已经存在的工作关系显式化，让用户能够从一张卡进入相关上下文，也让系统在生成建议时沿着可信关系补充背景。

记忆网不是传统知识库，也不是要求用户维护的知识图谱。它服务于“沉淀 -> 关联 -> 调用 -> 建议 -> 再沉淀”的工作闭环。

## 2. 产品目标

### 2.1 核心目标

用户保存或查看一张记忆卡时，可以快速建立、查看和使用与其他记忆卡的关系；下一次提问时，系统可以将已确认的关系作为召回和解释依据。

### 2.2 成功标准

- 用户能在保存记忆卡时完成关联，而不需要进入复杂的图谱编辑器。
- 用户能从一张卡片看到最有价值的上下文关系，并在一次点击内进入目标卡。
- 用户能理解每条关系“为什么存在”，包括关系类型、创建时间和来源。
- 关系能够提升相关记忆召回覆盖率，但不会明显增加误召回。
- 用户不需要维护“孤立”“过期”“待整理”等额外状态。

### 2.3 非目标

- 不做移动端记忆网。
- 不做 Neo4j 等重型图数据库。
- 不做 GraphRAG 或 Agentic RAG 的完整方案。
- 不自动把后台隐式记忆展示为用户可管理的记忆卡。
- 不要求用户为每张卡补齐关系。
- 不引入复杂的关系权重、生命周期和图谱治理页面。

## 3. 核心概念

### 3.1 记忆卡

记忆卡是用户可以查看、编辑、删除和手动调用的显式工作记忆，至少包含：

- 标题
- 正文
- 记忆类型
- 关键词
- 项目或业务范围
- 来源
- 创建时间和更新时间

### 3.2 关系

关系表示两张记忆卡之间具有明确工作意义的连接。关系包含方向、类型、来源和创建时间。

示例：

```text
客户 A 反馈首页转化率低
        --导致-->
首页改版进入下个版本
        --被替代-->
旧版首页方案
```

### 3.3 记忆网

记忆网由显式记忆卡和已确认关系组成。默认以当前卡片为中心展示局部关系，不直接展示全量复杂图谱。

后台隐式记忆可以参与关系推荐和回答召回，但不作为用户可见的节点进入记忆网编辑界面。这样既保留系统补充上下文的能力，也不突破现有的可见记忆边界。

## 4. 关系类型

1. **相关于**：两张卡属于同一主题或工作上下文，但不存在更明确的因果或替代关系。
2. **支持**：一张卡为另一张卡提供事实、反馈、数据或判断依据。
3. **导致**：一张卡描述的事实、问题或决策促成了另一张卡。
4. **解决**：一张卡记录的方案或动作解决了另一张卡描述的问题。
5. **替代**：新方案、新结论或新规则替代旧方案或旧结论。
6. **反驳**：一张卡中的证据或结论与另一张卡存在明确冲突。

### 4.1 关系方向

关系以“来源卡 -> 目标卡”保存。

例如：

```text
客户反馈 --支持--> 版本优先级判断
版本优先级判断 --替代--> 上一版排期结论
```

在用户界面中可以用自然语言展示为：

> “客户反馈”支持“版本优先级判断”

### 4.2 关系建立规则

- 用户手动建立的关系直接生效。
- AI 推荐的关系必须由用户确认后才生效。
- 同一对卡片、同一方向、同一关系类型只保留一条有效关系。
- 删除关系不会删除任一记忆卡。
- 删除记忆卡时，同时删除与该卡相关的关系。
- 关系不要求用户填写长说明；说明字段可选，建议不超过 100 字。
- 关系建立后允许单独编辑关系类型和说明。

## 5. 核心用户流程

### 5.1 新建记忆卡时关联

这是“进入记忆卡之前关系的关联”的主要入口。

1. 用户填写标题和正文。
2. 系统根据标题、正文、关键词和项目，推荐最多 5 张相关记忆卡。
3. 用户在保存前选择需要关联的卡片。
4. 用户为每张关联卡选择关系类型，默认推荐“相关于”。
5. 用户确认保存记忆卡和关系。
6. 保存完成后进入新卡详情，并展示已建立的关系。

关键要求：

- 关联步骤是保存流程中的轻量步骤，不单独进入图谱编辑器。
- 用户可以跳过关联直接保存。
- 用户不需要看到“没有找到关联卡”“孤立记忆”等提示。
- 若系统没有足够把握，只展示搜索入口，不强行推荐关系。

### 5.2 从记忆卡列表建立关联

1. 用户在记忆卡列表选中一张卡。
2. 点击“关联记忆”。
3. 在右侧抽屉中搜索或选择目标卡片。
4. 选择关系类型并确认。
5. 列表中的关系数量和卡片详情同步更新。

### 5.3 从记忆卡详情查看关系

详情页只展示当前卡片的直接关系：

- 关联卡片标题
- 关系类型
- 关系方向
- 项目或关键词
- 最近更新时间

点击关系项后，打开目标卡详情；保留返回路径，用户可以回到原卡继续浏览。

### 5.4 在记忆网中浏览

记忆网入口提供两种视图：

1. **列表视图**：默认视图，适合查找和处理。
2. **关系视图**：以选中卡片为中心，展示一到两层关系。

关系视图只承担发现和导航，不承担复杂编辑。用户可以点击节点查看卡片摘要，点击关系线编辑关系，点击“关联记忆”新增关系。

### 5.5 AI 推荐关系

当用户新建或编辑记忆卡时，系统可以给出：

> 可能与以下记忆有关

每条推荐需要展示：

- 目标卡片标题
- 推荐关系类型
- 一句话推荐理由
- “确认关联”和“忽略”操作

AI 推荐不等于自动建立。用户未确认的推荐关系不进入记忆网，也不参与正式的关系扩展召回。

## 6. 页面方案

### 6.1 记忆网首页

页面结构：

```text
顶部：页面标题 / 搜索 / 新建记忆卡
左侧：项目、关键词、关系类型筛选
中间：关系卡片列表或局部关系图
右侧：选中卡片摘要、关系详情、进入卡片
```

首页默认展示最近使用或最近更新的记忆卡关系，不展示空状态标签，不把“未建立关系”作为需要处理的问题。

### 6.2 保存记忆卡弹窗

保存流程分为两步：

1. **内容确认**：标题、正文、类型、关键词。
2. **关系关联**：推荐卡片、搜索卡片、选择关系类型。

关联区域必须允许用户跳过。保存按钮的文案保持为“保存记忆卡”，不要改成“完成图谱构建”。

### 6.3 记忆卡详情页

详情页信息层级：

1. 标题和正文。
2. 来源、项目、关键词、更新时间。
3. 关联记忆。
4. 被引用情况。
5. 编辑、删除、关联记忆等操作。

“关联记忆”采用列表呈现，默认按关系类型和更新时间排序。关系视图作为辅助入口，不替代详情页的信息阅读。

### 6.4 对话页中的关系上下文

当系统通过关系扩展召回记忆时，回答引用区展示：

```text
本次参考
客户 A 试用反馈
  通过“支持”关联到
版本优先级判断
```

用户可以查看参与回答的卡片，但不需要看到内部检索分数、向量距离或隐藏记忆 ID。

## 7. 数据模型

### 7.1 memory_relations

```sql
CREATE TABLE memory_relations (
  id TEXT PRIMARY KEY,
  source_memory_id TEXT NOT NULL,
  target_memory_id TEXT NOT NULL,
  relation_type TEXT NOT NULL,
  note TEXT,
  source_type TEXT NOT NULL DEFAULT 'manual',
  confidence REAL,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  FOREIGN KEY (source_memory_id) REFERENCES memories(id) ON DELETE CASCADE,
  FOREIGN KEY (target_memory_id) REFERENCES memories(id) ON DELETE CASCADE,
  CHECK (source_memory_id <> target_memory_id),
  CHECK (relation_type IN (
    'related',
    'supports',
    'causes',
    'solves',
    'supersedes',
    'contradicts'
  )),
  CHECK (source_type IN ('manual', 'confirmed_recommendation'))
);
```

### 7.2 字段规则

- `source_memory_id`：关系起点。
- `target_memory_id`：关系终点。
- `relation_type`：关系类型，存英文枚举，界面展示中文。
- `note`：用户可选的关系说明。
- `source_type`：关系来源。只有用户手动建立或确认 AI 推荐的关系可以写入。
- `confidence`：仅用于保存 AI 推荐被确认时的原始置信度，不直接作为用户可见评分。
- `created_at`、`updated_at`：用于展示和后台权重计算。

### 7.3 唯一性

建议增加唯一索引：

```sql
CREATE UNIQUE INDEX idx_memory_relations_unique
ON memory_relations(source_memory_id, target_memory_id, relation_type);
```

反向关系不自动合并。例如：

```text
A --支持--> B
B --反驳--> A
```

两条关系可以同时存在，因为它们表达的工作含义不同。

## 8. 关系推荐与检索联动

### 8.1 推荐关系生成

关系推荐只面向用户可见记忆卡，输入包括：

- 新卡标题和正文
- 关键词、项目、记忆类型
- 最近相关的显式记忆卡
- 已存在的关系

推荐过程：

1. 通过全文检索获取关键词相关卡片。
2. 通过向量检索获取语义相关卡片。
3. 合并并重排，筛选最多 5 张候选卡。
4. 对每个候选卡预测关系类型和简短理由。
5. 仅将候选结果展示给用户，等待确认。

### 8.2 关系扩展召回

关系只作为 hybrid RAG 的补充信号，不替代全文检索、向量检索和重排。

建议流程：

```text
当前问题
  -> 全文检索 + 向量检索
  -> 选出高相关记忆卡
  -> 沿已确认关系扩展 1 跳
  -> 对扩展卡片重新计算相关度和新鲜度
  -> 最终保留 Top 3-5 张进入回答
```

约束：

- 默认只扩展 1 跳，避免关系链过长导致上下文污染。
- 关系扩展卡的优先级低于用户手动指定卡。
- “反驳”和“替代”关系需要保留，不能因为语义相似度低而直接过滤。
- 被替代的旧卡可以参与回答，但需要在依据中明确其时间和替代关系。
- 后台隐式记忆不直接出现在关系图和用户可管理列表中。

## 9. 权重与治理

用户不维护关系权重和生命周期，系统后台处理以下信号：

- 当前问题与关系两端卡片的相关度。
- 关系类型的解释价值。
- 关系的新鲜度。
- 目标卡是否被新结论替代。
- 关系是否被用户多次确认或使用。
- 来源权重：用户手动建立或确认的关系高于系统推测关系。

关系推荐被忽略不代表关系不存在，只表示本次不建立。系统不得反复强提示同一条已被忽略的推荐，除非相关卡片内容发生明显变化。

## 10. 可见性与安全边界

### 用户可见

- 用户手动保存或添加的记忆卡。
- 用户手动建立的关系。
- 用户确认过的 AI 推荐关系。
- 本次回答使用的显式记忆卡及其关系路径。

### 仅后台可用

- 系统自动抽取的隐式记忆。
- 未经确认的潜在关系。
- 检索分数、向量距离、重排分数。
- 关系推荐的内部置信度和候选日志。

禁止：

- 自动把潜在关系写入正式关系表。
- 将隐藏记忆显示成关系网节点。
- 通过关系网暴露隐藏记忆的标题、正文或内部编号。
- 因删除一条关系而删除记忆卡。
- 用关系数量评价用户的记忆质量。

## 11. 分阶段交付

### Phase 1：显式关系基础能力

- 新增 `memory_relations` 表。
- 支持用户在保存前关联已有记忆卡。
- 支持记忆卡详情查看直接关系。
- 支持编辑和删除关系。
- 支持记忆网列表视图。

验收：

- 用户可以跳过关联并正常保存。
- 用户可以建立、查看、编辑、删除关系。
- 删除记忆卡不会留下无效关系。
- 关系只出现在显式记忆卡之间。

### Phase 2：关系推荐

- 新卡保存前推荐相关记忆卡。
- 推荐关系类型和推荐理由。
- 支持确认、忽略和去重。

验收：

- 未确认的推荐不进入数据库。
- 同一关系不会重复展示。
- 推荐失败不阻塞记忆卡保存。

### Phase 3：关系辅助召回

- 对高相关卡片进行一跳关系扩展。
- 在回答引用区展示关系路径。
- 增加新旧结论、替代关系的时间处理。

验收：

- 手动指定卡 100% 保留。
- 关系扩展不会超过回答上下文限制。
- 无依据的关系扩展不会被包装成确定性结论。

### Phase 4：局部关系视图

- 以当前卡为中心展示一到两层关系。
- 支持节点点击、关系线点击和返回原卡。
- 支持按项目、关键词和关系类型过滤。

验收：

- 关系图在常见桌面窗口中可读。
- 节点和关系线不会遮挡关键文字。
- 列表视图与关系视图数据一致。

## 12. 评估指标

### 产品指标

- 保存记忆卡时完成关联的用户比例。
- 关系推荐确认率。
- 从关系网进入目标记忆卡的成功率。
- 关系网辅助下的记忆卡调用率。
- 用户在连续追问中补充背景的次数变化。

### 质量指标

- 关系类型人工判定准确率 >= 85%。
- 已确认关系的目标卡命中率 >= 80%。
- 关系扩展后有效引用比例 >= 85%。
- 用户手动指定记忆卡保留率 = 100%。
- 隐藏后台记忆误展示次数 = 0。
- 删除卡片后的无效关系数量 = 0。

## 13. 与当前 1.0 的关系

当前 `docs/brief.md`、`docs/product-design.md`、`docs/spec.md` 和 `docs/plan.md` 仍以 1.0 的“记忆卡沉淀与调用”为准。记忆网方案属于后续能力设计，实施时应沿用现有四个锚点：

1. PC 客户端。
2. 用户可见的手动记忆卡。
3. 隐藏的后台记忆。
4. 全文检索 + 向量检索 + 重排的混合召回。

记忆网上线后，关系是记忆卡的辅助结构，不改变用户可见记忆卡的来源规则，也不改变“用户必须手动确认后才能产生可见内容”的原则。

## 14. 参考项目

以下项目用于借鉴产品交互、双向链接、关系模型和本地优先实现方式：

- [Zettelgarden](https://github.com/Zettelgarden/Zettelgarden)：本地优先卡片和双向链接。
- [MemoryGraph](https://github.com/memory-graph/memory-graph)：类型化记忆关系和关系查询。
- [mnem](https://github.com/Uranid/mnem)：本地知识图谱与混合检索。
- [Graphiti](https://github.com/getzep/graphiti)：时间关系、来源追溯和增量更新。
- [Foam](https://github.com/foambubble/foam)：双向链接、反向引用和局部图谱浏览。

这些项目只作为设计和技术参考，不代表记忆大师 1.0 直接引入图数据库、GraphRAG 或自动构图。
