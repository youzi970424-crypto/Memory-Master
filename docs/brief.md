# Brief｜记忆大师 1.0

> 2026-10-09 对齐：[PRD](product-design.md) 为产品需求统一入口，现有实现与缺口见其第 9 章。跨项目、跨时间记忆污染治理属于质量要求，尚未完整验收。

- **目标用户与场景**：高频决策型知识工作者，优先是产品经理。在需求评审、版本规划、复盘沉淀、客户反馈分析等场景中，用户每天会产生大量分散在会议、聊天、文档、网页和脑海中的工作记忆，希望在下一次遇到问题时，不用重新翻记录和解释背景，就能直接调用过去的结论、判断和经验，获得更贴合上下文的建议来推进工作和辅助决策。
- **要验证的核心假设（一条）**：把用户日常工作信息沉淀成结构化记忆卡后，通过“用户可见记忆卡 + 系统后台记忆”分层存储，并以 BM25 关键词召回为当前默认链路、向量检索为配置可用后的增强链路，在下一次提问时自动或手动调用相关记忆，能够稳定生成比通用对话更有上下文、更可执行的建议，同时显著减少用户重复解释背景和重复查找历史信息的成本。
- **成功判据（可观察）**：用户能够持续完成记忆沉淀；在真实工作问题中系统可以稳定召回相关记忆卡；回答中引用来源清晰可见；建议内容明显优于无记忆参与的普通对话；用户在连续追问中无需反复补充背景；用户主观感知到该产品确实帮助自己推进工作、减少遗漏判断并提升决策效率。
- **不做（non-goals）**：不做移动端；不做复杂记忆网与 GraphRAG；不做多助手身份体系；不做浏览器插件式采集；不做企业级多系统连接器与跨系统搜索；不让用户维护复杂记忆状态；不把系统后台自动沉淀的隐式记忆直接暴露给用户管理。

产品形态判断（L6-L7 谱系）：**工作台 + 检索增强工作流**。以 PC 端为主，围绕“沉淀 -> 调用 -> 建议 -> 再沉淀”形成固定主链路，不需要 Agent 级动态编排；当前阶段核心在于高质量记忆召回、权重治理和可解释建议，而不是复杂自主推理。
